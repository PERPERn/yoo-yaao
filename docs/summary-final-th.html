1. ไอเดียในหนึ่งหน้า

กลุ่มเป้าหมายDigital nomad, remote worker และผู้เกษียณชาวต่างชาติที่อยากอยู่ไทยหลายเดือน รวมทั้งผู้ถือหรือผู้สนใจวีซ่า DTV, LTR และ Retirement
ปัญหาไม่รู้ว่าวีซ่าไหนเหมาะกับตัวเอง (กฎเปลี่ยนบ่อย บล็อกให้ข้อมูลขัดกันเอง) · พลาดรายงานตัว 90 วันแล้วโดนปรับ · ไม่รู้ว่าเอเจนต์คนไหนไว้ใจได้และราคาไม่โปร่งใส
ทางแก้Visa Finder บอกวีซ่าที่เหมาะภายใน 60 วินาที โดยอ้างแหล่งทางการทุกข้อ · Stay Tools (ปฏิทินรายงานตัว 90 วัน, ตัวนับวันพำนัก, checklist) · Local Buddy คนท้องถิ่นช่วยพาไปทำธุระ · เอเจนซี่ที่ผ่านการตรวจใบอนุญาตแล้ว พร้อมแชท ส่งงาน และรีวิว
จุดต่างข้อมูลทุกข้อมีแหล่งอ้างอิงและวันที่ตรวจล่าสุด · ไม่ขายวีซ่าเอง แต่จับคู่กับเอเจนซี่ที่ตรวจตัวตนและใบอนุญาต TAT แล้ว (ระบบฐานข้อมูลบังคับให้ตรวจก่อนอนุมัติ) · ใช้ฟรีเป็นหลัก
ผลที่คาดหวังช่วยให้ชาวต่างชาติพำนักนานขึ้นและใช้จ่ายในไทยมากขึ้น ซึ่งส่งเสริมการท่องเที่ยวระยะยาว · สร้างรายได้เสริมให้คนไทย (Buddy) และธุรกิจท้องถิ่น (coworking, เอเจนซี่)

2. โมเดลธุรกิจ: รายได้ 3 ทาง

B2C: Pro

$8/เดือน หรือ $59/ปี สำหรับระบบเตือนและซิงก์ข้อมูล บวกค่า affiliate ประกันและ eSIM

B2B: ธุรกิจ

Featured listing $49/เดือน บวกค่า lead และแพ็กเกจ Verified Agent สำหรับเอเจนซี่

C2C: Local Buddy

คิด commission 20% ต่อการจองบัดดี้แต่ละครั้ง

3. สิ่งที่สร้างเสร็จแล้ว (ใช้งานได้บนเว็บจริง)

ฝั่งผู้ใช้ (นักท่องเที่ยว / nomad)

  • หน้าแรกแบบ scroll story: แต่ละฉากค้างไว้จนอนิเมชันเล่นจบ, มีโมเดล 3D จาก Blender (ในฉาก 90 วันแสดงเป็นเส้น), พื้นหลัง shader และคลิปเดโม
  • วีซ่าและเครื่องมือ: Visa Finder, หน้าวีซ่า 5 ประเภท, เครื่องคิดรายงานตัว 90 วัน (ส่งออกไฟล์ปฏิทิน .ics ได้), ตัวนับวันพำนัก, checklist เอกสาร
  • เมืองและบัดดี้: หน้าเมือง (กรุงเทพ เชียงใหม่ ภูเก็ต), Local Buddies, หน้าราคา และหน้าสถานะการจ่ายเงินพร้อมอนิเมชันเมื่อจ่ายสำเร็จ
  • บัญชีผู้ใช้: login ด้วยลิงก์ทางอีเมล, เมนูโปรไฟล์ที่ header (รูป ชื่อ ข้อความ ปุ่ม Log out), ตั้งค่าโปรไฟล์ครั้งแรก (ชื่อ รูป สัญชาติ วีซ่า วันเข้า เมือง)
  • แชทกับเอเจนซี่: กด "Message" ที่เอเจนซี่ได้ทันที · รับไฟล์งานที่เอเจนซี่ส่ง → กดยืนยันว่าได้รับ → ให้ดาวและเขียนรีวิว
  • ช่องวันที่: คลิกแล้วเปิดปฏิทินให้เลือกได้ทุกช่อง

ฝั่งธุรกิจ (แยกออกมาที่ /business)

  • สมัครเป็นพาร์ทเนอร์: ต้องกรอกเลขใบอนุญาต TAT หรือเลขทะเบียนบริษัท และมีหน้าอธิบายขั้นตอนการตรวจสอบ
  • พอร์ทัลพาร์ทเนอร์: ดู lead และอัปเดตสถานะ, แก้ไข listing, แชทกับลูกค้า, ส่งงานพร้อมแนบไฟล์

ฝั่งผู้ดูแล (/admin)

  • Dashboard: KPI, กราฟรายได้แยก B2C/B2B/C2C, traffic, สถานะระบบ, sales funnel
  • อนุมัติใบสมัคร: ต้องติ๊ก checklist ตรวจตัวตนและใบอนุญาตให้ครบก่อน แล้วเลือกเองว่าจะผูกกับ listing ไหน
  • จัดการอื่นๆ: จ่าย lead ให้เอเจนซี่, เปิด/ปิด listing, เปลี่ยน role ผู้ใช้

4. ความปลอดภัย

  • ควบคุมสิทธิ์ที่ฐานข้อมูล: มี role 3 แบบคือ user, partner และ admin โดยใช้ Row Level Security · ผู้ใช้เปลี่ยน role ของตัวเองไม่ได้ · แต่ละคนเห็นเฉพาะข้อมูลของตัวเอง
  • การอนุมัติพาร์ทเนอร์: ฐานข้อมูลปฏิเสธการอนุมัติหรือการตั้งสถานะ "จ่ายแล้ว" ถ้ายังไม่ได้ตรวจตัวตนและใบอนุญาต แม้แต่ admin ก็ทำไม่ได้
  • แชท ไฟล์งาน และรีวิว: เข้าถึงได้เฉพาะลูกค้าของงานนั้น เอเจนซี่ที่ได้รับมอบหมาย และ admin · ระบบตั้งชื่อผู้ส่งเองจึงปลอมตัวไม่ได้ · ข้อความแสดงเป็นข้อความธรรมดาจึงฝังโค้ดไม่ได้ · รีวิวได้เฉพาะลูกค้าที่งานเสร็จแล้ว และได้ครั้งเดียว
  • ไฟล์รูปและงาน: จำกัดขนาดและชนิดไฟล์ · แต่ละคนอัปโหลดได้เฉพาะในโฟลเดอร์ของตัวเอง
  • อื่นๆ: ใส่ security headers (CSP, HSTS) · ป้องกันการพาไปเว็บอื่นหลัง login (open redirect) · คีย์ลับไม่เคยถูกส่งไปที่เบราว์เซอร์ · ก่อนเปิดเป็น public ได้สแกน repo แล้วไม่พบคีย์หลุด
  • การทดสอบ: ทุก migration ทดสอบด้วยผู้ใช้ปลอมแล้ว rollback (ชุดส่งงานและรีวิวทดสอบผ่าน 33/33)

5. คุณภาพและการทดสอบ

  • Type check และ build: astro check ไม่มี error และ build ผ่าน
  • ทดสอบหน้าเว็บ: ไล่ทดสอบจริงทุกหน้า 42 หน้า ไม่มี console error และไม่มีการเลื่อนแนวนอนที่ความกว้าง 375px
  • Accessibility: axe ผ่านเรื่อง contrast, ลำดับหัวข้อ, landmark และการกดด้วยคีย์บอร์ด · ขนาดเป้ากดอย่างน้อย 24px
  • มือถือ: ไม่โหลดโมเดล 3D และ shader บนจอเล็ก หน้าจึงเปิดเร็วขึ้น · ตัววิดีโอโหลดเมื่อกดเล่นเท่านั้น
  • ฟอนต์และดีไซน์: Bricolage Grotesque, Public Sans และ Anuphan (ภาษาไทย) · โทนสี Jade & Marigold · ใช้ธีมสว่างโดยตั้งใจ

7. สิ่งที่ต้องตั้งค่าเอง (ยังรอดำเนินการ)

  1. Supabase → Authentication → URL Configuration: Site URL = https://yoo-yaao.vercel.app · Redirect URLs = https://yoo-yaao.vercel.app/** และ http://localhost:4321/**
    ถ้ายังไม่ตั้ง ลิงก์ login จะพาไปที่ localhost:3000
  2. ตั้งบัญชีตัวเองเป็น admin: login 1 ครั้ง แล้วรันใน SQL Editor: update public.profiles set role='admin' where lower(email)='อีเมลคุณ';
  3. Supabase: เปิด Leaked password protection และตรวจว่า Confirm email ยังเปิดอยู่
  4. ไม่บังคับ: ใส่คีย์ Stripe test และ service-role key ใน Vercel เพื่อให้จ่ายเงินจริง (ตอนนี้เป็นโหมดเดโมที่ไม่ตัดเงิน) · ต้องการ login ด้วย Google ให้เปิด Google provider แล้วตั้ง PUBLIC_AUTH_GOOGLE=1

8. ข้อจำกัดที่ควรรู้ และสิ่งที่ต่อยอดได้

  • ข้อมูลตัวอย่าง: ตอนนี้ยังไม่มีเอเจนซี่จริงในระบบ หน้า experts และ admin จึงใช้ข้อมูลตัวอย่างที่ติดป้ายบอกไว้ · traffic และรายได้ใน dashboard ก็เป็นข้อมูลตัวอย่าง จนกว่าจะเชื่อม Vercel Analytics และ Stripe
  • ยังไม่ได้ทดสอบด้วยบัญชีจริง: แชทแบบ realtime ระหว่าง 2 บัญชี และการส่งงานแบบเต็มลูป ต้องรอตั้งค่าข้อ 7 ก่อน
  • ยังไม่มีอีเมลแจ้งเตือน: ระบบเตือนของ Pro และการแจ้งตอนเอเจนซี่ส่งงาน ยังไม่ส่งอีเมลจริง (ต้องใช้บริการส่งเมล เช่น Resend)
  • ต่อยอดได้ (ไว้เล่าตอน pitch): เครื่องคิดค่าปรับ overstay, checklist 7 วันแรกในไทย, แชร์ผล Finder, web push, ชวนเพื่อน, ทริปเมืองรองระหว่างพำนัก, แจ้งเตือนผ่าน LINE, ขยายไปประเทศอื่นใน SEA
