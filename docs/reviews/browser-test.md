## ต้องแก้ก่อนโชว์ให้กรรมการลองบนมือถือ

B1

### หน้าแรกบนมือถือกว่าจะใช้งานได้ต้องรอหลายวินาที

ที่วัดได้

เว็บจริง: LCP 4.4 วินาที, TBT 2,640 ms, ใช้งานได้เต็มที่ (TTI) 7.7 วินาที, เวลาที่ผู้ใช้กดแล้วค้างได้นานสุด 1,590 ms

ต้นเหตุ

- สคริปต์ฉาก 3D `hero3d.js` ใช้ CPU 1.4 วินาที (ในเครื่องที่รัน) และมี long task 738 ms
- `three.module.js` 719 KB และไลบรารี shaders `js.*.js` 2.5 MB (ผ่านการบีบอัดบนเว็บจริงเหลือ 705 KB และ 186 KB) ถูกดาวน์โหลดตอนเปิดหน้าแรก ใน Chrome headless ผมเห็นว่าไฟล์ 2.5 MB ถูกโหลดจริงที่วินาทีที่ 1.26 ส่วนเครื่องที่มี WebGPU ยังไม่ได้ทดสอบ โค้ดส่วนที่ไม่ได้ใช้ในไฟล์นี้ประมาณ 964 KB
- ภาพที่เป็น LCP (`hero-fallback.webp`) ไม่ได้ตั้ง `fetchpriority="high"` และมี CSS 2 ไฟล์ที่บล็อกการวาดหน้า (ประมาณ 750 ms ในเครื่องที่รัน)
- มีงานที่ทำให้เบราว์เซอร์ต้องคำนวณ layout ซ้ำ (forced reflow) จาก `motion.js`

ที่ไม่ใช่ปัญหา

บนเครื่องเดสก์ท็อปแรง (ไม่จำกัด CPU) LCP แค่ 464 ms และ TBT 307 ms ปัญหาเกิดกับมือถือที่ช้า ซึ่งเป็นเครื่องที่ผู้ใช้กลุ่ม nomad ใช้อยู่บ่อย

แนวทางแก้

เลื่อนการโหลดฉาก 3D และ shaders ไปหลังวาดหน้าแรกเสร็จ (idle) หรือโหลดเมื่อเลื่อนมาถึง · ใส่ `fetchpriority="high"` ให้ภาพ hero · ลด CSS ที่บล็อกการวาด · ใช้ภาพนิ่งแทนฉาก 3D บนมือถือ

มาตรฐาน

Core Web Vitals: LCP เกิน 4.0 วินาทีอยู่ในช่วง "แย่"

คำสั่งถัดไป

`/impeccable optimize` หรือ `/agent-skills:webperf` เมื่อติดตั้ง repo นี้

ข้ามรอบที่เลยแล้วไปแสดงรอบที่ยังมาไม่ถึง หรือเปลี่ยนหัวข้อเมื่อทุกรอบผ่านมาแล้ว

### ใส่วันเข้าไทยล่วงหน้าไม่ได้

ที่วัดได้

B7

### `/about` คำขอวิดีโอ `demo.webm` ถูกยกเลิก

ที่วัดได้

คำขอ `/media/demo.webm` (2 MB) จบด้วย `ERR_ABORTED` ทุกครั้งที่โหลดหน้านี้ น่าจะเป็นการ preload ที่เบราว์เซอร์ยกเลิกเอง ไม่กระทบผู้ใช้ แต่ควรตั้ง `preload="none"` ถ้ายังไม่ได้ตั้ง

วิธีทดสอบ ข้อจำกัด และสิ่งที่ยังไม่ได้ทดสอบ

- **skills ที่ใช้:** ผมโคลน `addyosmani/agent-skills` ไปอ่านเท่านั้น (ไม่ได้ติดตั้งเข้า `~/.claude`) และทำตาม workflow ของ `browser-testing-with-devtools` (reproduce → inspect → ดู console/network/a11y tree/performance) กับเกณฑ์ Core Web Vitals ของ `performance-optimization` และโหมด Deep ของ `/webperf` ที่ใช้รายงาน Lighthouse JSON
- **ไม่มี Chrome DevTools MCP:** skill ต้องการ MCP ตัวนี้ ซึ่งยังไม่ได้ตั้งค่า ผมจึงใช้ Playwright กับ Chrome ที่เปิดด้วยโปรไฟล์ใหม่ (ไม่ผูกกับ Chrome ของคุณ ตรงกับหลัก Profile Isolation ของ skill) และ Lighthouse แทน
- **ข้อมูลจาก browser:** ถือเป็นข้อมูลที่ไม่น่าเชื่อถือ ไม่มีเนื้อหาในหน้าที่พยายามสั่งให้ทำอะไร
- **เซิร์ฟเวอร์ทดสอบ:** build ในเครื่องเสิร์ฟด้วย Python `http.server` (ไม่มี gzip/brotli, HTTP/1.1, ไม่มี API) เพราะ `astro preview` ใช้กับ adapter ของ Vercel ไม่ได้ จึงทดสอบ API, admin ที่ดึงข้อมูลสด และ chat ไม่ได้ในรอบนี้
- **ที่ยังไม่ได้ทดสอบ:** INP จากการใช้งานจริง · ข้อมูลผู้ใช้จริง (CrUX) · เครื่องที่มี WebGPU/GPU จริง · Safari และ Firefox · เครื่องมือถือจริง · login, Supabase, Stripe, chat · การรัน Lighthouse หลายรอบเพื่อหาค่าเฉลี่ย
- **เว็บจริงอาจต่างจาก commit ล่าสุด:** ผมไม่ได้ตรวจว่าเวอร์ชันที่ deploy ตรงกับ `583f60b`
